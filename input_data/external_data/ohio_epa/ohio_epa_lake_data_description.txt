We don’t have a good lake identifier (that I’m aware of) so you will probably have to use grep or similar.

The field “parameter” includes the names of the various parameters. I include the field parameters (D.O., temperature, pH, and depth), as you will likely need the depth field. The field “logval” contains the log10 values for chlorophyll, pheophytin, sulfate and DOC [log10(result times 1000); the times 1000 bit is to avoid having negatives] – if the result was less than the RL, I substitute ½ the RL prior to the log transformation.  
 
The fields “leftx” and “rightx” are to return results that can be run through the fitdistrplus package, should one of the parameters be highly truncated (not the case here). The “x” added to the field name is to deal with Postgres.

The field “water_depth” is included in the station table, but I think it is inconsistently populated, so probably just ignore it.

We had a problem with DOC on the filters used in the field, and identified and corrected the problem circa 2018. I’m not sure how consistently we collected both TOC and DOC in lakes, but a simple plot of DOC on TOC would help screen results. I included TOC in the query. 

I don’t have ready access to pre-1999 lakes data. 

Let me know if you have any questions or trouble with the attachment.
